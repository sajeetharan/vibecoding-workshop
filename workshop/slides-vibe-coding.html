Welcome to Cursor: AI-First Code Editor

A brief intro for developers new to Cursor.

What is Cursor?

  • VS Code fork with AI built-in
  • No extra plugins needed
  • Models: Claude, GPT-4, Sonnet
  • Works offline (some features)

Why Cursor for This Workshop

  • Faster vibe coding workflow
  • Codebase-aware suggestions
  • Chat and edit in one place
  • Built for pair programming

Speaker Notes

  • Cursor is a fork of VS Code with AI integrated natively.
  • Key advantage: codebase-aware context means AI understands your whole project, not just one file.
  • Today you'll use Cursor's chat, commands, and tab completion to ship faster.
  • Question: "How many have used VS Code before?" (Show of hands)
  • If VS Code familiar: Cursor feels like VS Code + a smart teammate in the same window.

Install Cursor (2 Minutes)

  1. Go to cursor.com
  2. Download for Windows / Mac / Linux
  3. Run installer, sign in with email (free plan OK today)
  4. Open the app and create a new folder workspace
  5. Or use Cmd+K / Ctrl+K to trigger AI commands

💡 Tip: If you already have VS Code projects, Cursor can import settings. No need to reconfigure.

Speaker Notes

  • Cursor is free to download and use with free tier.
  • For this workshop, free tier is plenty. Premium features (unlimited fast requests) can come later.
  • Keep it simple: just download and run. No credential setup needed yet.
  • First-time users: Cursor prompts you for a model choice. Claude is recommended for this workshop.

The Three Core Cursor Moves

1️⃣ Chat (Ctrl+K / Cmd+K)

Ask questions about code, request refactors, debug issues. Chat sees your entire codebase context.

2️⃣ Tab Completion (Tab)

Start typing. Cursor predicts next line or function. Press Tab to accept, Esc to reject.

3️⃣ Edit (Ctrl+L / Cmd+L)

Select code, press Ctrl+L, describe what to change. Cursor edits inline with a diff preview.

Keyboard Shortcuts Cheat Sheet

Editing

  • Ctrl+K – Chat with AI
  • Ctrl+L – Edit selected code
  • Ctrl+I – Generate code inline

Navigation (Same as VS Code)

  • Ctrl+P – Quick file open
  • Ctrl+/ – Toggle comment
  • Ctrl+D – Multi-cursor select

🎯 Muscle memory note: Learn one shortcut per day. Start with Ctrl+K (chat) and Ctrl+L (edit).

How to Chat with AI in Cursor

  1. Press Ctrl+K (Windows) or Cmd+K (Mac)
  2. A chat box appears at bottom
  3. Type your question: "Why is this API endpoint returning 500?"
  4. Press Enter or click Send
  5. AI reads your current file and open tabs for context
  6. Response appears in the chat panel
  7. Click the code block to apply suggestions

Speaker Notes

  • First time using chat: the context awareness is mind-blowing. AI doesn't just know syntax—it knows YOUR code.
  • Pro tip: Mention specific file names or functions to narrow context. Example: "In app.js, why does validateEmail() reject valid addresses?"
  • Chat persists during the session, so you can ask follow-up questions naturally.

Tab Completion: Real-Time Coding Partner

How it works: Start typing code. After a few characters, a gray suggestion appears. Press Tab to accept or Esc to dismiss.

✅

Best for:

Repeating patterns, boilerplate, function signatures you've used before

⚠️

Be cautious with:

Security-critical code, business logic, edge cases. Always review before accepting.

Codebase Context: Your Secret Weapon

Cursor reads your files to give smarter answers.

What Cursor Can See

  • Open files and tabs
  • File structure and dependencies
  • Your project's naming patterns and conventions
  • Package.json, tsconfig, .env (not secrets)

💡 Pro tip: Keep related files open in tabs. Cursor uses them for better context. Close unrelated tabs to avoid noise.

First Cursor Prompt: A Template

📋 Template:
"I want to [specific task]. Current files: [list relevant files]. Success looks like [acceptance criteria]. What should I start with?"

Example:

I want to add a logout button to my React app.
Current files: src/App.js, src/components/Header.js.
Success looks like: button appears in header, clicking it clears auth token and redirects to login.
What should I start with?

Settings and Model Choice

  • Open Settings: Ctrl+, (same as VS Code)
  • Search "Cursor Settings" for AI model choice
  • Recommended models for this workshop:
    • Claude Sonnet – Best accuracy, reasoning
    • GPT-4 – Fast, good at code generation
    • Claude Opus – Best for complex multi-file refactors

Note: Free tier has usage limits. If you hit limits, switch to a different model or wait 24 hours.

Common Cursor Gotchas and Fixes

❌

Chat doesn't see my changes

→ Save the file first (Ctrl+S). Cursor reads saved state.

❌

Completion feels slow or irrelevant

→ Keep workspace focused. Close tabs for other projects.

❌

AI suggestion conflicts with my code style

→ Press Esc to reject. Train the model by accepting suggestions that match your style.

Ground Rules for AI-Assisted Building

  • Small steps over big rewrites
  • Read before accepting generated code
  • Validate behavior after each change
  • Track assumptions explicitly
  • Keep a human decision log

Prompt Pattern 1: Scope First

📋 Prompt: "Propose a 60-minute implementation plan. Keep scope small, list files to change, add acceptance criteria."

❌

Vague: "Build a full app with all features and make it scalable."

✅

Sharp: "Build POST /api/reports only. Validate input. Return error JSON. Time box: 20 mins."

Prompt Pattern 2: Focused Build

🎯 Prompt: "Implement feature X with the smallest maintainable change. Do not touch unrelated files."

🔨

Surgical approach: One file, one feature, minimal blast radius

👀

Easier to review: Your teammate can understand the change in 30 seconds

🐛

Fast debugging: Broke something? Revert one diff, not 10

Prompt Pattern 3: Review and Risk

🔍 Prompt: "Review this diff as a senior engineer. List bugs, edge cases, and regressions by severity."

Critical (🔴): Null pointer, SQL injection, infinite loop

Major (🟠): Memory leak, broken API contract, performance cliff

Minor (🟡): Typo, inconsistent naming, missing comment

Prompt Pattern 4: Debug Fast

🔧 Prompt: "Given this error and current code, list 3 likely root causes and lowest-risk fix first."

1️⃣

Reproduce

Exact steps to break it

2️⃣

Hypothesize

3 possible root causes

3️⃣

Patch

Try lowest-risk fix first

4️⃣

Verify

Reproduce same steps again

Deploy Commands

gcloud auth login
gcloud config set project YOUR_PROJECT_ID
gcloud services enable run.googleapis.com cloudbuild.googleapis.com artifactregistry.googleapis.com
gcloud run deploy fuel-finder-live --source app --region us-central1 --allow-unauthenticated

Speaker Notes

  • Three commands: configure project, enable services, deploy.
  • Google Cloud Run buildpacks auto-detect Node.js, build, deploy in seconds.
  • No Docker wrestling—we ship fast to stay within 2-hour window.
  • Question: "Who's deployed code before?" (Quick show of hands)
  • Each person runs these commands on their laptop (live demo + parallel work).
  • Your live URL will be ready in 1-2 minutes per deployment.

Post-Deploy Verification

  • Service URL loads
  • /api/health returns status ok
  • Create at least 3 fuel or gas status reports
  • UI reflects newly posted station data instantly
  • At least one report is flagged as suspicious by AI check

Common Failure Cases and Fixes

  • Wrong active project in gcloud
  • Required APIs not enabled
  • Region mismatch or quota issues
  • Validation errors from malformed payload

Recovery habit: read exact error text first, then ask Cursor with context.
